# 恢复指南

## 概述

本指南介绍标书审查过程中的失败恢复——如何诊断、续接和处理不可恢复的错误。

> **重要**：恢复不保证从进程中断点精确续跑。它使用平台机制诊断状态，通过 `contextMode="continue"` 创建新运行来延续工作。

## 失败分类

### 1. 成员任务失败

委派的专业智能体超时、崩溃或输出不完整时：

1. **检查运行记录** — 通过平台的运行检查（`InspectRuns`）识别失败原因和后续运行。
2. **检查是否有在途后继** — 如果重试或后续运行已在进行中，等待它完成，不要同时发起新任务。
3. **带上下文续接** — 使用平台的续接机制，提供原始 `run_id` 和 `contextMode="continue"`。这会创建一个**新运行**继承先前上下文；不是从精确中断点重启进程。
4. **关系不明时停止** — 不要猜测续接哪个运行；记录不确定性。

### 2. 契约 Schema 缺失或损坏

契约 Schema 文件缺失、损坏或身份错误时：

- 校验器返回结构化错误（exit 1 或 2）。
- **不得绕过**契约检查——这是硬性门槛。
- **从发行版绑定源恢复**：选择已独立验证的安装/团队发行版，读取 `shared/contracts/schemas/` 前先核发行版本/ref 与预期文件哈希。原子替换损坏文件，禁止手工编辑 Schema；替换后逐份核六类精确 `$id`、`$schema`、`contract_version` 身份及预期 SHA-256，全部通过后才能恢复校验。

### 3. Schema 校验失败

数据产物未通过 JSON Schema 校验时：

- 检查输出中的 `schema_errors`，定位具体字段和错误信息。
- 修复数据产物，而不是修改 Schema。
- 修复后重新校验，不得跳过校验直接进入业务检查。

### 4. 业务规则违规

结构校验通过但业务规则失败时：

- 查看 `violations` 数组中的规则 ID 和受影响路径。
- 常见问题：覆盖未闭合、未解决工具失败、缺双边证据、版本绑定不匹配。
- 修复特定产物后重新校验。

### 5. 工具失败（PDF 渲染等）

平台工具运行失败时：

- 在报告的未完成项中如实记录。
- **永远不**静默跳过受影响的检查。
- 工具恢复后重新运行，不得在无证据时声称检查通过。

## 版本失效

审查周期后材料发生变化时：

- 生成新 `manifest_id`。
- 绑定旧 `manifest_id` 的覆盖和发现全部失效。
- 仅重新检查受影响部分（通过 SHA-256 依赖识别）。
- 重查完成前不得复用旧结论。

## 禁止操作

- 不修改原始投标文件来修复校验错误。
- 不删除违规记录以获得干净退出码。
- 不在未修复根本数据问题的情况下换参数重试。
- 不在未通过 `InspectRuns` 验证运行关系的情况下续接运行。
- 不手工编辑 Schema 文件——始终从已验证的发布源恢复。

## 平台恢复机制

DesireCore 平台提供：

- **运行检查**（`InspectRuns`）— 查看任何智能体运行的完整历史和状态；识别失败来源和唯一后继。
- **续接**（`contextMode="continue"`）— 创建一个新运行继承先前上下文并延续工作；这不是从精确中断点重启进程。
- **中断** — 在方法明显错误时停止运行中的任务。

这些操作作用于智能体执行层，不作用于数据。恢复始终从诊断数据状态开始。
